Setup

This project is a continuation of the work done during CST-463-01 during the Spring 2026 semester. With this project, I am seeking to expand upon the capabilities of the robot from the virtual assistant project to make it act more like a robotic pet.
The newest files for the program can be found below.

Program Files: robotClientV9.py, robotServerLocalTEXTV4.py, robotServerLocalV4.py, aiModule.py, speech.py

The server must be ran on an external device, preferably a laptop that uses something such as Apple's M series SOCs or dedicated graphics. To run the server, you need one of the server files (robotServerLocal or robotServerLocalTEXT), aiModule.py, and speech.py programs listed above within the same directory. Also, Python version 3.12.10 is recommended. The server file can simply be executed to start it. You will need to provide your IP address on the local network to the robot for it to connect. Also, when the server is ran for the first time, it will have to download the local models it uses, which may take a little while depending on your connection.

The required libraries for the server and its associated modiules can be installed via: pip install PyAudio gTTS SpeechRecognition pygame "transformers[torch]" opencv-python Pillow

The client program for the robot should be ran using Python version 3.12.10. Also, the MutoLib library must be retrieved from the download made available at the Muto-RS Robot Repository.
It should be installed from the file provided by them. Other libraries needed can be installed through: sudo python -3.12 -m pip install numpy Pillow opencv-python

Weekly Logs

Week 1 - Initial Goals

Week 1: This week, I laid out initial plans to create a set of programs that enables the robot to act as a robotic pet, such as a Furby. Extra motions for the robot has also been created.
Program Files: robotEmotes.py

Week 2 - Initial Client/Server

Week 2: This week, the virtual assistant project code has been reworked to utilize threads to fit the future functionality of the project. Edge detection has also been tested.

Week 3 - Local AI Module

Week 3: This week, the module used for AI has been completely rewritten to utilize local models instead of Google Gemini to bypass token limitations. They also provide faster responses depending on the hardware. Additionally, the robot's client program has been updated to add idle functions and a follow function. There are now three active threads in the program running simultaneously as a result of this change.

Week 4 - Restructuring Program Logic

Week 4: This week, work has been done to restructure the code for the robotClient and robotServer programs. A text input version of the robotServer is also now available.

Week 5 - New Movement and Idle State Additions

Week 5: New versions of the robotClient and robotServerLocalTEXT have been made available for the new movement functionality. Also, the aiModile.py file has received an update.

Week 6 - Refining the Movement Program and Research

Week 6: A new version of the robotClient titled robotClientV4_1 is now available to fix an oversight with the robot not stretching when it stands up from laying in idle in the idle state. Also, research has been done into applications of monocular depth and edge detection for automated walking. Additionally, an emotion system to influence the robot's movement speed and idle sequences is being planned, with the current values and new movements already having been mapped out.

Week 7 - Robot Positivity

Week 7: This week, a basic implmentation of robot positivity discussed last week has been added.

Week 8 - Modified Movements

Week 8: Adjustments have been made to aspects of the code to improve expressivity of the negative emotion. Such adjustments include modification of the functions used for shuffling, sitting, and laying so they can be done slower while not impacting the original function calls throughout the rest of the program.

Week 9 - New Movements

Week 9: Two new emotes for negativity have been added, which are gaze and slam. Shuffle has also been given its own function to simplify how it is called. Additionally, the Peacock Spider Wave has been adjusted to be slowed down by a little bit. Positivity is also now referenced in the commandHandling function to modify how the robot performs laying, sitting, gazing, and shuffling based on its emotional state. aiModule.py has also been updated alongside a new server version.

Week 10 - Passive Camera Thread

Week 10: A basic implmenetation of a passive camera thread that runs when no command or idle action is being taken has been implemented. The face detection code in the follow thread has been fixed, additional actions have been added for it, and that same logic is utilized in the passive camera thread to recognize faces when between commands and idling. Also, the follow thread idling for too long will now reduce positivity, while both the follow and passive camera threads will now increment positivity upon seeing a face.
Program Files: robotClientV8.py

Week 11: If the passive camera state is active when idle is beginning, the idle state now utilizes blocking once adding something to indicate that it is about to start so it will wait until the inner passive camera loop has ended to run.
